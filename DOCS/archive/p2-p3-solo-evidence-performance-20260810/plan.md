## Acceptance criteria

- P2 records exact revision, Node/npm/browser versions, date, routes, and viewport set.
- Every material public claim is traceable to evidence or explicit absence and has an allowed and prohibited interpretation.
- The CDC adaptation records `met`, `partly met`, `not met`, or `not applicable`; it reports no CDC score.
- Both AI review passes are independently prompted, explicitly non-human, and never represented as user research, a quote, a participant observation, or authority.
- Fresh tests and browser evidence cover semantic structure, navigation/focus, keyboard behavior, reflow, status text, console/network failures, and the claim gate; limitations remain explicit.
- P3 defines throttling, headed browser, cold/warm cache treatment, at least seven samples per compared scenario, median, nearest-rank p95, success signals, and noise boundaries.
- P3 reports home `map_preview.png`, dashboard MapLibre ready, and external/CARTO resource settle separately; bundle size is contextual only.
- Product code changes only if repeated runtime evidence shows a clear benefit and the smallest reversible change preserves initial comprehension, keyboard access, and real link behavior.
- Actions decisions cite official sources and use immutable full-SHA pins; no unpinned third-party action is introduced.
- Public/dashboard test and build gates pass, or exact failures are recorded; all owned listeners/browsers are stopped and generated `dist`, browser cache, temporary logs, and dependency directories are removed before handoff.
- Final state is `ready-for-integration` only; no staging, commit, push, merge, rebase, cherry-pick, deployment, registry edit, or worktree operation occurs.

- No scientific-method validation, new modeling result, raw-data change, recovery/causality/fairness/policy/ranking conclusion, or production deployment.
- No dependency addition, broad architecture rewrite, warning suppression, synthetic bundle-only performance conclusion, or third-party action outside official GitHub `actions/*` repositories.

## Risks and constraints

- A solo proxy can find content and technical defects but cannot prove that intended users understand the science.
- Browser throttling is an emulation with local-server latency and one Windows/Chromium/GPU stack; it is not field data.
- External CARTO/style/tile responses can fail or vary independently of repository code; external settle must remain a separately labeled proxy.
- `map_preview.png` is below the first viewport but is inside a real router link; changing fetch timing must not weaken link semantics, alternative text, keyboard reachability, or the map card's eventual visual context.
- GitHub hosted-runner behavior and official action releases can change; the record pins the access date and immutable commit evidence used for this candidate.
